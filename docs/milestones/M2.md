# Milestone M2: The GitHub Actions adapter and the failure model

A plain-language summary for a maintainer who wants to understand every part and may be new to Go.

## What was built

- `internal/ci`: the types every CI provider shares (`Status`, `Repo`, `FailedStep`, `CommitStatus`, `StepLog`), the `Provider` interface, `ValidCommit`, and `ParseRemote`, which turns a git remote URL into a `Repo`. It does no I/O.
- `internal/ci/github`: the GitHub Actions implementation of `ci.Provider`. It finds a token, asks GitHub for the workflow runs of a commit, decides the status, lists the failed steps, and resolves the ID of one failed step to that step, its commit and its log.
- `internal/failure`: pure code that turns a resolved step log (`ci.StepLog`) into a `Failure`: a sanitized, size-capped excerpt, the known files the excerpt mentions, and the `regreen.yml` check the step belongs to (or "not fixable"). It does no I/O.
- One new direct dependency, `github.com/google/go-github/v93` v93.0.0 (decision D31). It brings one indirect dependency, `github.com/google/go-querystring`.
- Tests that use no network (GitHub is faked with `httptest`), fuzz tests, an opt-in live test, and decisions D31 to D42.

**Nothing calls these packages from the command line yet.** `regreen` still prints help and its version. The packages wait for M3, which will add the wait loop and the MCP tools.

## How the pieces connect

```
git remote URL --ci.ParseRemote--> ci.Repo
Repo + commit  --Provider.CommitStatus--> ci.CommitStatus{Status, Commit, Failed []ci.FailedStep}
Repo + step ID --Provider.FailureLog--> ci.StepLog{Step, Commit, Log (untrusted text), Partial}
StepLog + checks + known files --failure.Build--> failure.Failure
```

The step ID comes back from the agent in M3, so it is not trusted. `FailureLog` does not take the caller's word for which step and commit an ID names: it reads the job from GitHub and returns the step and the commit it found there in the `ci.StepLog`. The caller compares `StepLog.Commit` with the commit it is fixing and stops on a mismatch, then passes the whole `StepLog` to `failure.Build` (decisions D33 and D42).

Files in `internal/ci/`:

- `ci.go`: the data types and the interface. `Provider` has three methods: `Name`, `CommitStatus` and `FailureLog` (decision D32). `FailedStep.ID` is opaque to callers. `StepLog` is what `FailureLog` returns: the step, the commit, the log text, and `Partial`, which says the log is incomplete or could not be limited to the step (decision D42).
- `remote.go`: `ParseRemote` accepts `https`, `http`, `ssh` and `git` URLs and the `git@host:owner/name` form. It drops any user name, password and port, and its errors never repeat the input, because a remote can contain a token. It rejects local paths, a query or fragment, odd host characters, a host with an empty label (a leading, trailing or doubled dot), an IPv6 host, an scp-like user with characters outside `A-Z a-z 0-9 . _ -`, extra path segments and control characters.

Files in `internal/ci/github/`:

- `auth.go`: `Token` looks in `GH_TOKEN`, then `GITHUB_TOKEN`, then runs `gh auth token --hostname github.com` (decision D38). A cancelled lookup returns the context's error.
- `provider.go`: `New`, the options, and `CommitStatus`. `WithBaseURL` (for tests) must be `https`, or `http` on a loopback host; `New` refuses anything else. It lists the runs whose `head_sha` is the commit. If any run is unfinished, the status is `pending`. Otherwise it keeps the newest run of each (workflow, event, branch) group and judges those: `success`, `skipped` and `neutral` pass, everything else fails (decisions D34 and D35). For each failing run it lists the jobs and turns each failed step into a `ci.FailedStep`. If GitHub says there are more runs or jobs than it sent (`total_count` larger than what arrived), or there are more than 10 pages, that is an error and not a guess.
- `id.go`: `encodeID` and `parseID` for `gha-<run>-<job>-<step>` (decision D33). `parseID` refuses anything over 64 bytes without repeating it, and accepts exactly that shape.
- `logs.go`: `FailureLog`. It reads the job and refuses the ID unless the job is completed and failed and the ID's step number names one of its failed steps (0 only for a failed job with no failed step). It rebuilds the step and the commit from the job, asks for the log location (which must be an absolute URL with a host), downloads the log with a client that has no token, keeps at most the last 8 MiB, cuts out the lines in the step's time window, and strips GitHub's timestamps and markers (decisions D33, D36 and D37). If the window selects nothing, the log is empty and `Partial`, rather than the whole job log.
- `live_test.go`: `TestLive`, which runs against the real GitHub only when you set two environment variables.
- `fake_test.go`: the in-memory fake GitHub API the other tests use. `testdata/` holds two job logs.

Files in `internal/failure/`:

- `failure.go`: the `Failure` struct, `Limits`, `DefaultLimits` and `Build`. `Build` takes a `ci.StepLog`, copies its step and commit, runs `TrimLog`, then `ExtractFiles` on the trimmed text, then `MatchCheck`. `Truncated` is set when `TrimLog` cut anything or the step log was `Partial`.
- `trim.go`: `TrimLog` (decision D41). In order: replace invalid UTF-8, normalize line endings (U+2028, U+2029 and U+0085 become newlines), remove terminal escape sequences, control characters and all Unicode format characters, tidy blank lines, cut over-long lines (marked ` …[line cut]`), then keep the last lines that fit 200 lines and 16 KiB (a header line says how many earlier lines were dropped, counting blank lines at the start of the kept part, which go too). `MaxBytes` below 18 is raised to 18.
- `files.go`: `ExtractFiles` (decision D40). It splits the text into tokens, cleans each (position suffixes like `:12:5`, a leading `./`), and keeps those that are in the caller's set of known files. The last token before a line-cut marker is ignored, because it may be half a name. A second pass finds known names that contain spaces or delimiter characters, such as `pages/[id].tsx` or `docs/my file.md`, when a space, quote, bracket or similar character (or the start or end of the line) surrounds them, or when they end an absolute path.
- `match.go`: `MatchCheck` (decision D39).

`Build` gives a `Failure` with `Fixable == true` only when exactly one check matched. Otherwise `Check` and `Command` are empty and the failure must be reported to a person, not fixed.

## Go idioms used and why

**Interfaces are satisfied implicitly, and a compile-time assertion keeps that honest.** In Go a type implements an interface just by having its methods; there is no `implements` keyword. That is flexible, but a typo in a method name only fails where someone uses the type as the interface. The line `var _ ci.Provider = (*Provider)(nil)` in `internal/ci/github/provider_test.go` assigns a nil `*Provider` to a blank variable of the interface type. It costs nothing at run time, and `go vet` and `go test` fail if `*Provider` stops satisfying `ci.Provider` (the line is in a test file, so `go build` does not compile it).

**Functional options.** `New(token, opts ...Option)` takes any number of options, and `Option` is `func(*options)`. `WithBaseURL(u)` and `WithHTTPClient(c)` return a function that sets one field. `New` starts with an empty `options` value and calls each option on it. A caller writes `New(tok)` or `New(tok, WithBaseURL(srv.URL))`, and a new option later does not change any existing call. They are in `provider.go`; the tests use them to point the provider at a fake server.

**`httptest.Server` as a fake GitHub.** `net/http/httptest` starts a real HTTP server on a random local port inside the test, with a handler you write. `fake_test.go` builds a small in-memory GitHub from it: runs, jobs, logs, and a record of each request. The provider talks to it over real HTTP, so the tests exercise the real client code (URLs, query strings, pagination, the redirect to a log) with no network. The fake also records the `Authorization` header, which is how a test checks that the log download carries no token.

**`errors.Is` and `errors.As` through `%w`.** `fmt.Errorf("...: %w", err)` keeps `err` inside the new error. `errors.Is(err, context.Canceled)` then answers true however many layers wrap it, which is how the tests check that a cancelled lookup returns the context error and not `ErrNoToken`. `errors.AsType[T](err)` finds an error of type `T` in the chain and returns it. It is the generic form of `errors.As`, and it needs no variable to point at. `logs.go` uses it for typed checks: `apiFailure` looks for go-github's `*ErrorResponse`, `*RateLimitError` and `*AbuseRateLimitError` to report only their HTTP status, and `downloadCause` and `apiFailure` look for a `net.Error` to tell a timeout from other network errors. Here wrapping is avoided on purpose: an error from `http.Client.Do` (a `*url.Error`) or from reading the body can contain the signed URL, so `downloadCause` replaces every download error with one of a few fixed texts (`download failed`, `download timed out`, `too many redirects`, the context's error, and so on) and never wraps the original.

**Bounded reads.** Code that reads a response from another host must not trust its size. `readTail` in `logs.go` reads in 32 KiB chunks and, whenever the buffer reaches twice the limit, copies the last `limit` bytes to the front and drops the rest. Memory therefore stays near twice the cap however big the response is, and what is kept is the end. `io.LimitReader` (used for the config file in `internal/config/repo.go`) is the simpler tool: it stops reading after N bytes, so it keeps the start of the data. A log's failure is at its end, so the log reader keeps the end by hand. The same idea shows in `ExtractFiles`, which ignores tokens over 4096 bytes and only checks suffixes as long as the longest known path.

**Pointer fields and `GetX()` accessors in go-github.** go-github's response types use pointers for most fields (`*string`, `*int64`) so that a missing JSON field (`nil`) differs from an empty or zero one. Reading `run.Status` directly would panic on `nil`. Every such field has an accessor, `run.GetStatus()`, that returns the zero value when the pointer is `nil`. `provider.go` uses accessors everywhere, so a half-filled response is a wrong answer at worst, not a crash. The same accessors work on a `nil` struct pointer.

**Fuzz tests that state properties.** `FuzzTrimLog` and `FuzzExtractFiles` in `internal/failure/fuzz_test.go` do not compare against an expected string. They say what must hold for any input: the output of `TrimLog` is valid UTF-8, has no escape, control or format character, and is within the caps; `ExtractFiles` returns only known files, sorted, without duplicates. `go test` runs them once on the seed inputs; `-fuzz` generates many more. This is the right tool for code that reads untrusted text.

**Pure packages, checked by tests.** As in M1, `TestCIPackageIsPure` and `TestFailurePackageIsPure` read each non-test file's imports with `go/parser` and fail if one is `os`, `os/exec`, `net` or `net/http`. Everything these packages know comes in through arguments, so a test needs no temporary files and no server.

**Injected dependencies for testing.** `token` in `auth.go` takes a `getenv` function and a `gh` function as arguments, and the exported `Token` passes `os.Getenv` and `runGh`. A test can pass a fake environment and a fake `gh` and test the lookup order without touching the real ones. `Token` is the one-line wrapper that wires the real ones.

## What is deliberately not here yet

- The 45-second wait loop, the MCP tools, git operations, local state (M3). `CommitStatus` is a single call; nothing polls it.
- Any command that uses these packages.
- Retries, back-off on rate limits, and caching. A 403 or 429 is an error with its status.
- GitLab, Jenkins and other providers. `ci.Provider` is shaped so another adapter could be added; none exists.
- Deciding where the set of known files comes from (it must come from git, M3), and calling `Build` on the original failure's log.
- Running a fix, or re-running a check.

## Known limitations

- **A mapped, trimmed failure is still untrusted text.** The excerpt is safe to print (no escape sequences, no hidden or direction-changing characters, bounded in size), and the files it lists are limited to the known set. But a log can say anything in plain words, including text addressed to an agent. Showing the excerpt as quoted data and delimiting it in tool output is M3's job. Nothing here proves that a fix is logically correct.
- **Names with spaces or delimiter characters need clear boundaries.** The second pass of `ExtractFiles` finds `docs/my file.md` or `pages/[id].tsx` only when the start or end of the line, whitespace, a quote or a few punctuation characters surround the name, or when it ends an absolute path. A name directly followed by `.`, `]` or `>` is not found by that pass.
- **At most 2000 such names are searched.** If the known set holds more than 2000 paths with whitespace or delimiter characters, the second pass is skipped and none of them is extracted (decision D40).
- **Steps are cut by one-second timestamps.** GitHub reports step times to the second, so two fast steps in the same second can bleed into each other, and an excerpt can include a neighbour's lines. When a step's window is unusable or selects nothing, the log is empty and marked `Partial` (so `Failure.Truncated` is set), instead of falling back to the whole job log, whose other steps would feed `Files`.
- **Composite actions and reusable workflows report as their calling step.** A failure inside one is attributed to the step (or job) that called it, so name matching may not find the check.
- **GitHub Enterprise is not supported.** Any host other than `github.com` is an error. A token for github.com is never sent to another host.
- **No retries on rate limits or network errors.**
- **A failure ID binds to a commit only through the caller.** `FailureLog` returns the commit the job ran for, but cannot know which commit the caller is fixing; M3 must compare them (decision D42). A run-level failure has no log and no commit from `FailureLog`.
- **A stale unfinished run keeps a commit `pending`.** Every run for the commit must complete, including a superseded one; a run that never finishes blocks a final status.
- **More than 1000 runs for one commit, or 1000 jobs in one run, is an error.** So is an API listing that is shorter than its own `total_count`.
- **Only the last 8 MiB of a job log is read.** A failure that is not near the end of a very large log is not seen.
- **Windows line endings are kept on the lines until trimming.** A trailing `\r` is treated as part of the line ending when a timestamp is read and when a line is compared with `##[endgroup]`, but it stays in the text `FailureLog` returns; `TrimLog` then turns `\r\n` into `\n` (decision D36).
- **Check mapping is by name and command only.** A step whose name matches no check is `Fixable == false`, and a name that matches two checks at one level is ambiguous and also `Fixable == false` (decision D39).
- **Error files depend on the caller's known set.** `ExtractFiles` cannot tell a set taken from the original failing commit from one taken after the agent's edits; M3 must supply the right one (decision D40).
- **Format characters are deleted, not escaped.** Emoji joined with a zero-width joiner and soft hyphens lose a character (decision D41).
- **Verified by tests with a fake GitHub, not by use.** `TestLive` exists but was not run when this was written; behaviour against the real API (log URL redirects, step timestamps, rate limits) is untested.
